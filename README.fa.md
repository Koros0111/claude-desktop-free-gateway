# claude-desktop-free-gateway — راهنمای فارسی

> نسخه انگلیسی: [README.md](README.md)

> گیت‌وی رایگان: استفاده از **Claude Desktop** با **مدل‌های رایگان OpenCode** از طریق API سازگار با Anthropic — همراه با پل vision و tools.

**چرا این پروژه؟** Claude Desktop انتظار API پیام‌های Anthropic را دارد. این گیت‌وی سبک لوکال آن را به یک نمونه لوکال `opencode serve` ترجمه می‌کند (تنها مسیری که می‌تواند از سطح رایگان OpenCode استفاده کند)، با fallback خودکار مدل، مسیریابی اسکرین‌شات/vision و پل تصمیم‌گیری Cowork/tools.

- 🔄 fallback ترتیبی بین مدل‌های رایگان (`combo.json`)
- 🖼️ مسیریابی vision: اسکرین‌شات‌ها به‌صورت file part به serve ارسال می‌شوند (ماتریس تست‌شده داخل README انگلیسی)
- 🧰 پل tools: مدل *تصمیم* می‌گیرد (`text` / `tool_use`)، Claude Desktop *اجرا* می‌کند (حلقه stateless)
- 📡 اندپوینت‌های Anthropic در `/v1/messages` و `/v1/models`، سازگار با OpenAI در `/v1/chat/completions`، بازپخش SSE و `/health`
- 🔒 کاملاً لوکال: وقتی پوشه پروژه شناسایی شود جلسات همان‌جا اجرا می‌شوند (در غیر این صورت ایزوله در `./sandbox/`)، فقط مقادیر نمونه در `.env.example` (فایل `.env` واقعی هرگز کامیت نمی‌شود)

## شروع سریع

1. `cp .env.example .env` — سپس `GATEWAY_API_KEY` و `OPENCODE_SERVE_PASSWORD` را تنظیم کنید
2. روی `run_gateway.bat` دابل‌کلیک کنید (یا `uvicorn gateway:app --host 127.0.0.1 --port 3457`)
3. در Claude Desktop — آدرس گیت‌وی `http://127.0.0.1:3457`، احراز هویت `bearer`، کلید برابر `GATEWAY_API_KEY`

# راهنمای کوتاه

## اجرا

روی `run_gateway.bat` دابل‌کلیک کنید (یا در ترمینال اجرایش کنید).
محیط `.venv` فعال می‌شود، گیت‌وی روی `http://127.0.0.1:3457` بالا می‌آید
و اگر `opencode serve` روی `:4097` نباشد خودش آن را اجرا می‌کند.

## تنظیمات Claude Desktop

- آدرس گیت‌وی: `http://127.0.0.1:3457`
- طرح احراز هویت: `bearer`
- کلید API گیت‌وی: مقدار `GATEWAY_API_KEY` داخل `.env` را بچسبانید
  (پیش‌فرض `local-dev-key-12345` — آن را با یک مقدار محرمانه عوض کنید).
- فهرست مدل‌ها (کشف خودکار از `GET /v1/models`):
  `claude-sonnet-4-5`، `claude-opus-4-5`، `claude-haiku-4-5`
  (هر سه به یک زنجیره مدل رایگان در `combo.json` نگاشت می‌شوند).

## ترتیب مدل‌ها

فایل `combo.json` را ویرایش کنید: هر نام مستعار به یک فهرست ترتیبی نگاشت می‌شود.
گیت‌وی به ترتیب تلاش می‌کند و روی خطا / محدودیت نرخ / پاسخ خالی سراغ بعدی می‌رود.
مدل‌های سازگار با چت را اول و مدل‌های فقط-passthrough را آخر بگذارید.
بعد از ویرایش گیت‌وی را restart کنید.

## رفع اشکال

- خطای `401 invalid API key`: کلید داخل Claude Desktop با `GATEWAY_API_KEY`
  داخل `.env` یکی نیست. دقیقاً کپی کنید.
- خطای `502 upstream failed` / کد `429`: یک مدل زنجیره به محدودیت نرخ یا خطا خورده؛
  گیت‌وی بقیه را هم امتحان کرده. `GET /health` را چک کنید
  (`serve_reachable` باید `true` باشد) و بعداً دوباره تلاش کنید.
- خطای `401 auth-rejected` از serve: مقادیر `OPENCODE_SERVE_USERNAME/PASSWORD` داخل `.env`
  با نمونه serve در حال اجرا هم‌خوانی ندارد. نمونه اضافی
  `opencode serve` را ببندید (یا `.env` را اصلاح کنید) و گیت‌وی را restart کنید.
- نکته: درخواست‌ها کمی کند هستند (مدل‌های رایگان از طریق serve: ده‌ها ثانیه) و
  هر درخواست حدود ۲۰ هزار توکن ورودی از system prompt مربوط به opencode مصرف می‌کند.

## چرا عامل تکرار می‌کرد یا فایلی می‌نوشت که پیدا نمی‌شد (v3.1)

مدل‌های رایگان در کار با ابزار ضعیف‌اند و سه باگ داخل گیت‌وی همان چیزی را
می‌ساخت که شبیه «عامل فراموش‌کار» به‌نظر می‌رسید. هر سه رفع شده؛ متن داخل
نقل‌قول‌ها همان خطوطی است که قبلاً در لاگ دیده می‌شد.

- **مسیر پوشه‌ای که فاصله دارد نصف می‌شد.** `C:\Users\YOU\My Project` به‌صورت
  `C:\Users\YOU\My` خوانده می‌شد، بررسی وجود پوشه شکست می‌خورد و جلسه در پوشه‌ای
  دیگر اجرا می‌شد. حالا مسیر کامل خوانده می‌شود و اگر تطبیق زیاد از حد بود، فقط
  تا بلندترین پیشوندی که واقعاً یک پوشه موجود است کوتاه می‌شود — هرگز جلوتر.
- **فراخوانی‌های درستِ بدون پارامتر دور ریخته می‌شدند.** `TaskList {}` یک
  فراخوانی کامل است؛ dropping آن (`dropping tool_use 'TaskList' with empty
  input`) یعنی هرگز `tool_result` باز نمی‌گردد، پس مدل هر نوبت دوباره
  «اول فهرست تسک‌ها را چک می‌کنم» را تکرار می‌کرد. اکنون اسکیمایی که اعلام‌شده
  باشد و چیزی نخواهد، بدون تغییر رد می‌شود. فراخوانیِ فقط‌ناتمام (مثلاً
  `Write` با مسیر ولی بدون محتوا) هم forward می‌شود، چون کلاینت یک
  `tool_result` خطا با نام همان فیلد برمی‌گرداند و مدل در نوبت بعد اصلاحش
  می‌کند. فقط فراخوانی‌ای که هیچ مبنایی برای داوری ندارد حذف می‌شود —
  حذف کردن بی‌صداست و همین بی‌صدایی باعث تکرار می‌شد.
- **نام‌های نزدیک به نام درست دور ریخته می‌شدند.** دسکتاپ
  `mcp__tools__TaskList` را اعلام می‌کند؛ مدل‌های کوچک `TaskList`،
  `tasklist` یا با یک حرف فرق پاسخ می‌دهند. حالا هر مورد به همان ابزاری که
  کلاینت واقعاً اعلام کرده تصحیح می‌شود (`tool name '...' corrected to the
  declared '...'`); ولی نامی که به هیچ‌چیز نگاشت نشود همچنان رد می‌شود، چون
  فرستادن آن باعث خطای کلاینت در هر نوبت می‌شود.
- **پاسخ نیمه‌کاره حالا خودش را لو می‌دهد.** وقتی مدل به سقف توکن خروجی
  می‌رسد — یا JSON وسط فراخوانی بریده شده و salvage آن را می‌بندد — نوبت با
  `stop_reason: "max_tokens"` گزارش می‌شود نه `end_turn`، پس Claude Desktop
  دکمهٔ Continue را نشان می‌دهد به‌جای اینکه یک نصف جمله بدون راه ادامه بماند.
- **یک نوبت می‌تواند چند فراخوانی ابزار داشته باشد.** سقف قبلی چهار تا بود و
  یک مرحلهٔ موازی را به چند رفت‌وبرگشت تقسیم می‌کرد؛ حالا
  `GATEWAY_MAX_TOOL_USE_BLOCKS` (پیش‌فرض ۱۰) است و همین چیز است که ویرایش
  هم‌زمان چند فایل را دوباره مثل Claude اصلی حس می‌کند.
- **یک پاسخ متنی نوبت را با «قول» تمام می‌کرد.** prompted تصمیم JSON می‌خواهد؛
  وقتی مدل می‌نوشت «الان فایل را می‌نویسم»، گیت‌وی همان متن را جلو می‌فرستاد و
  همهٔ ابزارهای پیشنهادی دور ریخته می‌شدند. حالا یک بار دیگر سخت‌گیرانه JSON
  خواسته می‌شود (`decision-retry:` در لاگ) و بعد از
  `GATEWAY_PROMISE_STREAK_THRESHOLD` نوبتِ فقط-قول، خط `REPEAT GUARD` به مدل
  نشان داده می‌شود که تکرار را ممنوع و فراخوانی ابزار را دستور می‌دهد
  (افعال ارادی فارسی و انگلیسی هر دو شناسایی می‌شوند).
- **پوشه‌های موقت خودِ Claude پروژهٔ شما نیستند.** فایلی که در
  `local-agent-mode-sessions\...\outputs` نوشته شود واقعی ولی در Explorer
  دیده نمی‌شود، پس «فایل را نوشت» و «فایلی وجود ندارد» هر دو درست بود. این
  مسیرها هرگز به‌عنوان پروژه رتبه نمی‌گیرند (`GATEWAY_SCRATCH_MARKERS`) و
  یادداشت workspace از ابتدا پوشه را اعلام می‌کند و هشدار می‌دهد مسیر دارای
  فاصله باید کامل و داخل نقل‌قول داده شود.
- **صفر یعنی «خاموش» — جایی که گفته شده.** `GATEWAY_PROMISE_STREAK_THRESHOLD=0`
  گارد تکرار را کاملاً خاموش می‌کند (از طریق `PROMISE_GUARD`) و
  `GATEWAY_IMG_TTL_H=0` پاک‌سازی عکس‌ها را متوقف می‌کند. این کلیدها از
  `_int_env_zero` / `_float_env_zero` خوانده می‌شوند (صفر قبول، منفی رد)، چون
  خوانش معمولی صفر را به مقدار پیش‌فرض برمی‌گرداند.
- **stop reason صادق می‌ماند.** `max_tokens` فقط وقتی گزارش می‌شود که خودِ
  upstream بگوید پاسخ بریده شده (`info.finish` مثل `length`) یا خودِ گیت‌وی متن
  را کوتاه کرده باشد (fallbackهای ۴۰۰۰ کاراکتری و مسیر salvage در
  `_decision_worker`). مقدار `max_tokens` کلاینت به upstream فرستاده نمی‌شود:
  اسکیمای serve فیلد سقف خروجی ندارد و آن را بی‌صدا نادیده می‌گیرد (تست زنده:
  `{"max_tokens": 8}` پاسخ کامل با finish برابر `stop` گرفت)، پس حدس‌زدن بریدگی
  از روی شمارش توکن، پاسخ‌های کامل را «بریده» جا می‌زند و دکمهٔ Continue را
  دروغگو می‌کند. اندپوینت OpenAI هم همان شواهد را با `finish_reason` برابر
  `length` یا `stop` منعکس می‌کند.
- **کاتالوگ ابزار قابل حسابرسی است.** با `GATEWAY_TOOL_CATALOG=true`
  (پیش‌فرض)، هر درخواست ابزارهای اعلام‌شدهٔ کلاینت را در `tool_catalog.json`
  ادغام می‌کند (مسیر جایگزین با `GATEWAY_TOOL_CATALOG_PATH`): برای هر ابزار
  `description`، `has_schema`، `zero_arg`، `required` و `properties` — فقط نام و
  شکل اسکیما، هرگز محتوای پیام. این فایل دادهٔ ران‌تایم است (gitignore شده)؛
  برای بازبینی، مسیر را به یک پوشهٔ موقت بدهید تا درخت کاری کثیف نشود.
- **بازنویسی بی‌پایان یک فایل متوقف می‌شود.** نوشتن‌های موفق پشت‌سرهم در یک
  مسیر (شمارش از آخرین پیام شما؛ خطاها شمرده نمی‌شوند، دستور جدید ریست
  می‌کند): در ۳ با خط هدایت، در ۵ با رد نوشتن و متن خطا، در ۸ با یک نوبت
  متنی صادقانه. فایل‌های مختلف هیچ‌وقت با هم جمع نمی‌شوند.
- **هر پیام شما سقف ترن دارد.** بالای `GATEWAY_MAX_TURNS_PER_MESSAGE`
  (پیش‌فرض ۳۰، صفر یعنی خاموش) گیت‌وی ابزار پیشنهاد نمی‌دهد و با یک خلاصه
  متنی می‌بندد — تور نجات برای لوپ‌هایی که هیچ گاردی نمی‌شناسد. هرگز ۵۰۲ نه.
- **تصمیم گاردها روی دیسک می‌نشیند.** `GATEWAY_LOG_FILE` (پیش‌فرض
  `sandbox/_gw.err.log`، خالی یعنی خاموش) لاگ‌های گیت‌وی را در فایل هم
  می‌نویسد، چون uvicorn آن‌ها را فقط در ترمینال خودش نشان می‌دهد.

همهٔ کلیدها مقدار پیش‌فرض امن دارند: `GATEWAY_DECISION_JSON_RETRY`،
`GATEWAY_PROMISE_STREAK_THRESHOLD`، `GATEWAY_SCRATCH_MARKERS`،
`GATEWAY_MAX_TOOL_USE_BLOCKS`، `GATEWAY_PROJECT_LOG`، `GATEWAY_TOOL_CATALOG`،
`GATEWAY_MAX_TURNS_PER_MESSAGE`، `GATEWAY_LOG_FILE`،
`GATEWAY_CAPTURE_MAX_CHARS`، `GATEWAY_CAPTURE_KEEP`.
توضیح هر کدام در `.env.example` است. برای اشکال‌زدایی فراخوانی ابزار بدون اپ
دسکتاپ: یک بار گیت‌وی را اجرا کنید و `tool_catalog.json` را باز کنید — نام هر
ابزاری که Claude Desktop اعلام کرده به‌همراه کلیدهای الزامی و propertyهایش
ثبت می‌شود (بدون هیچ محتوای پیام). تست‌های آفلاین داخل ریپو
(`test_tool_parity.py`، `test_folder_space.py`، `test_repeat_guard.py`،
`test_agentic.py` — هر کدام با `python <suite>.py`) همان خطا را بدون شبکه و
بدون سرور بازپخش می‌کنند؛ هر مورد بالا پشت یک تست است. با
`GATEWAY_CAPTURE=1` هر ترن ابزارمحور هم به‌صورت سالم در `captures/` ذخیره
می‌شود — اول پیام‌ها (که همیشه می‌مانند)، بعد ابزارها؛ ابزار اضافه با یادداشت
`tools_dropped` کنار می‌رود و فایل‌ها همیشه JSON معتبرند.


## محدودیت‌ها (نسخه اول)

فقط چت متنی. ابزارها/computer-use بدون آن فعال نیستند. تصاویر با یادداشت جایگزین می‌شوند.
بلوک‌های `thinking` ارسال/بازگردانده نمی‌شوند.
اندپوینت‌های استریم وجود دارند ولی پاسخ کامل upstream را به‌صورت SSE بازپخش می‌کنند
(فراخوانی upstream به `serve` خودش غیراستریم است).
فراخوانی ابزار توسط مدل (bash/read/...) فعال می‌ماند (غیرفعال‌کردن آن‌ها مدل‌های رایگان را خراب می‌کند).
وقتی گیت‌وی پوشه پروژه را شناسایی کند جلسات همان‌جا اجرا می‌شوند (در غیر این صورت ایزوله در `./sandbox/`) —
مدل واقعاً به پروژه شما خواندن/نوشتن دارد، پس هر فراخوانی ابزار را نظارت کنید و هیچ رازی آنجا نگه ندارید.
توقف گیت‌وی با Ctrl+C (تمیز: نمونه serve خودش را هم می‌بندد).

## ابزارهای Cowork / computer-use (نسخه آزمایشی)

حلقه agentic مربوط به Cowork/Code حالا کار می‌کند: وقتی درخواست حامل `tools` باشد،
گیت‌وی یک پرامپت TOOL-DECISION می‌سازد، از زنجیره مدل رایگان upstream نظر می‌خواهد
و بلوک‌های معتبر `text` / `tool_use` در قالب Anthropic برمی‌گرداند.
کلاینت (Claude Desktop) ابزارها را اجرا می‌کند؛ گیت‌وی فقط تصمیم می‌گیرد
— خودش هیچ عملی اجرا نمی‌کند. حلقه چندمرحله‌ای کار می‌کند: هر نوبت تاریخچه کامل را حمل می‌کند
(`tool_use` به‌علاوه `tool_result`) و سمت گیت‌وی stateless است.

## تصاویر / اسکرین‌شات‌ها (نسخه آزمایشی، تست‌شده)

بلوک‌های تصویری Anthropic (base64 با فرمت PNG/JPEG، سطح بالا یا داخل `tool_result`)
رمزگشایی، اعتبارسنجی بایت‌جادویی و سقف‌گذاری می‌شوند
(`GATEWAY_MAX_IMAGES=5` و مجموع `GATEWAY_MAX_IMAGE_MB=4` در هر درخواست)،
زیر `sandbox/img/` ذخیره و به‌صورت file part به فراخوانی upstream در serve ضمیمه می‌شوند.
موارد اضافی با یادداشت `[N image(s) omitted: over slam limit]` کنار گذاشته می‌شوند؛
بلوک‌های خراب بدون خطا رد می‌شوند. ماتریس دقیق مدل‌ها را در README انگلیسی ببینید.

راهنمای ایمنی: هر فراخوانی ابزار را نظارت کنید؛ با کارهای فقط‌خواندنی شروع کنید؛
کار را داخل محدوده Claude Desktop نگه دارید؛ تا وقتی حلقه فقط‌خواندنی پایدار نشده
ابزارهای مخرب را فعال نکنید.
